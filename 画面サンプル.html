Moneytree（入金実績の取得）

費用
明細をAPIで取るには法人向けの「Moneytree LINK」の契約が必要です。料金は公開されておらず個別見積もりになるため、費用はかかる前提で見てください。個人向けアプリには外部から使えるAPIがありません。
契約しない方法
明細をCSVで書き出し、所定のフォルダに置いて読み込ませます。API契約は要りませんが、書き出しを毎日だれかが行う手間が残り、その日に書き出さなければ入金の検知が1日遅れます。書き出せる形式と列名は実物で確かめてから合わせます。
明細の反映は遅れることがある
Moneytreeは銀行から明細を定期的に取りに行く仕組みで、入金がその日のうちに出ないことがあります。夕方の入金が翌朝に反映されることもあるため、未入金アラートは予定日の1日後以降にしておくと、入金済みなのに「未入金」と送る誤報を減らせます。
口座の再連携で止まる
銀行側のパスワード変更や追加認証の期限切れで、明細の取得が止まることがあります。止まっていても画面上は「未入金」に見えるので、最後に明細を取れた日時を見て、古ければ経理に警告を出す仕組みを入れます。
振込名義の表記
摘要は銀行によって半角カナ・記号・長さが違い、長い名前は途中で切れることもあります。お客様ごとに本人・配偶者・親など複数の名義を登録し、親名義などで届いた同額の入金は「この入金ではないか」と人に確認させる形にしています。

Chatwork（通知の送信と返信の確認）

費用
API自体の使用料はかかりません。ただし送信者になるBot用アカウントを1人分用意するなら、そのユーザー分の料金がかかります。
送信者はトークンの持ち主
APIで送ったメッセージは、トークンを発行した人の発言として出ます。個人のトークンを使うと本人が送ったように見えるため、Bot用アカウントを作り、そのトークンを使ってください。Botは送信先のルームのメンバーにしておく必要があります。
トークンの管理
トークンはパスワードと同じ扱いです。プログラムや設定ファイルに直接書かず、環境変数などに置きます。再発行すると古いトークンを使う仕組みはすべて止まるため、再発行するときは使っている連携を洗い出してから行ってください（当社では2026年6月に再発行で既存の通知が止まったことがあります）。
回数の上限
APIには1つのトークンにつき5分あたり300回までの上限があり、メッセージ投稿は1ルームにつき短時間に送れる回数にも制限があります。入金確認の件数なら問題ありませんが、一度に大量の確認を送る運用にはしないでください。
返信の読み取りは直近100件まで
メッセージの取得は直近100件までです。会話の多いルームに送ると、返信が100件より前に流れて読み取れないことがあります。通知専用のルームを作るのが確実です。
返信ボタンを使ってもらう
返信ボタンで返された発言は、どの確認への返事かを確実に判定できます。返信ボタンを使わない発言は、その担当者の確認待ちが1件だけのときに限り返事とみなします。遅れの原因は「2 上棟が11月にずれたため」のように番号から書いてもらうと自動で記録されます。
組織の設定
組織によっては、管理者がAPIの利用を制限していることがあります。トークンを発行できない場合は管理者に確認してください。
LINE WORKS との違い
Chatwork は Bot 用アカウントのトークン1つで送信も返信の読み取りもでき、受け口のサーバーは要りません。返信ボタンも使えるので、どの確認への返事かを確実に判定できます。

LINE WORKS（通知の送信と返信の受け取り）

APIはあるか
公式の「LINE WORKS API 2.0」があり、Bot からトークルームにメッセージを送れます。設定は管理者が Developer Console（開発者向けの管理画面）で行います。
費用・プラン
契約プランによって Bot の数や使える機能が違います。導入前に、契約中のプランで Bot と API が使えるかを管理者に確認してください。返信を受け取る口（下記）を Cloudflare Workers に置く場合は、この件数なら無料枠に収まります。
返信の受け取りに「受け口」が要る
Chatwork と違い、LINE WORKS の Bot はトークルームの過去の発言を読みに行けません。担当者の返信は LINE WORKS から、こちらが用意した受け口（https のURL）へ送られてきます。受け取って貯めておく小さなプログラムを常時動かしておく必要があり、止まっている間の返信は記録されません。
返信ボタンがないので案件番号で答えてもらう
どの確認への返事かを判定する手段がないため、メッセージに案件番号を載せ、返信の先頭に書いてもらいます（例：A001 お客様に確認済みです／P04-3 2 上棟がずれたため）。番号のない発言は、その担当者の確認待ちが1件だけのときに限り返事とみなします。
準備（管理者の作業）
アプリを作って Client ID・Client Secret・サービスアカウント・秘密鍵を発行し、Bot を登録して受け口の URL を設定し、Bot を通知用のトークルームに招待します。トークルームの「チャンネルID」と、担当者・上長のユーザーID（またはログイン用のメールアドレス）も控えておきます。
鍵の管理
Client Secret・秘密鍵・Bot Secret はパスワードと同じ扱いです。プログラムや設定ファイルに直接書かず、環境変数などに置きます。受け口は Bot Secret で「LINE WORKS から来た通知か」を確かめてから記録します。
宛先（メンション）
Chatwork の [To] の代わりに、本文に <m userId="ユーザーID"> を入れて担当者を呼び出します。この書き方は公式の送信ページには載っておらず外部の解説で確認したものなので、本番前に実際の通知が担当者に届くかを確かめます。
書式と長さ
Chatwork のような枠や見出しの装飾がないため、見出しは【】で表します。1通は2,000字までです。原因の選択肢を増やしすぎないでください。

運用

実行する場所
1時間ごとに自動で動かします。社内PCで動かすと、電源が切れている間は止まります。常時動くサーバーやクラウドで動かすのが確実です。
個人情報
口座の明細とお客様名を扱うため、明細ファイルや実行記録の置き場所は閲覧できる人を絞ってください。チャットに流す内容も、ルームのメンバー全員が見られる前提で決めます。
このページの設定と原因
このページで保存した設定と選んだ原因は、このブラウザの中にだけ残るサンプルです。本番では「config.json を表示」の内容をプログラム側に移します。
